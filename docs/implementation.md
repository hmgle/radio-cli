# 实现说明

采用 Rust + SQLite + mpv + FFmpeg，面向 Linux。CLI 和 TUI 共用 `Store`、`Directory`、`Engine` 和 `Recorder`；TUI 的媒体工作线程拥有这些组件，界面通过容量为 16 的命令队列提交操作，通过共享快照接收状态。录音进度队列容量为 32，界面只在输入、尺寸或状态变化时重绘。

## TUI 交互与任务

界面分为普通、搜索、命令三种模式，输入模式隔离播放与退出快捷键。命令解析先处理 TUI 上下文，再复用 CLI 的 clap 参数校验；`shell-words` 只负责引号分词，不执行 shell。命令历史最多 100 条、任务消息最多 200 条，均仅保存在当前会话内。

来源、列表、详情、播放器、任务五个面板支持循环、编号、空间方向和鼠标切换；焦点使用青色粗边框、箭头和底部提示共同表达。窄终端改为上下布局，极矮布局共享列表与详情区域，通过焦点切换显示。输入光标和详情换行以 Unicode 显示宽度计算，搜索消抖 200 ms，列表刷新按 UUID 保留选择并屏蔽过时筛选结果上的操作。

目录获取与全量同步使用单独线程、SQLite 连接、取消标记和有界结果通道；媒体线程继续处理播放控制与录音进度。同步暂存数据不会覆盖旧目录，最终事务提交前再次检查取消；请求进行中取消需要等待当前请求结束或超时。任务完成后按最新筛选刷新列表。退出先请求取消并停止媒体，再等待目录线程回收。详见 [TUI 使用说明](tui.md)。

顶部播放信息来自 `Engine::Status`，与列表选择独立。码率、编码、语言等来自目录并注明来源，未知值不显示为实际的零码率；详情可查看当前请求地址（含备用线路），但不能保证这是 HTTP 重定向后的最终 CDN 地址。播放器继续使用 ICY/音频元数据更新曲名。

## 数据与目录

SQLite 使用 WAL、5 秒写锁等待、4 MiB 页缓存和 `user_version` 迁移。电台记录同时保存原始字段与供查询使用的归一化列；国家、码率和热门排序有索引。名称等组合查询用绑定参数和 `instr` 做字面子串匹配，避免 `%`、`_` 被解释为通配符；分页最多 1,000 条。随机选台使用流式蓄水池抽样，内存与目录大小无关。

全量刷新按名称分页，每页 1,000 台、最多 200,000 行，响应解压后上限为 16 MiB。剔除名称为空或 UUID 无效的上游条目，但分页偏移仍按原始返回数推进。分页结果进入临时表并按 UUID 去重；最后一个事务更新目录与同步时间。API 不提供快照隔离，因此同步期间远端目录变化可能导致少量漏项，下次完整刷新可纠正；不把分页同步描述为严格一致的远端快照。未出现在新目录中的记录标记失效，不物理删除，以保留收藏和历史引用。

服务器发现优先查询 `_api._tcp.radio-browser.info` SRV，失败时尝试官方服务器列表。最多尝试三台服务器。自定义 API 只访问指定地址。目录请求使用 `radio-cli/版本` User-Agent，成功起播后尝试点击上报；失败不阻断播放。没有全量后台可用性探测，目录提供的可用状态也不能保证当前网络能连接源站。

## 播放与进程

mpv 禁用个人配置、脚本、视频与终端输入，使用私有运行目录中的 Unix Socket JSON IPC。订阅 `metadata`、`pause` 和 `volume`，依据 `playback-restart` 确认起播，才写历史和上报点击。

起播默认超时 12 秒。初始地址失败后仅刷新一次 UUID，继续尝试不同的最新地址、原始地址与显式备用地址；不按名称推断同一电台。显式选台失败后停止；随机模式最多尝试五个电台。缓存目标为 3 秒、压缩包预算 2 MiB，不预连接下一台。

每个媒体会话持有文件锁，退出时关闭 mpv 并等待回收。Linux 子进程设置父进程死亡信号，前台被 SIGKILL 时不会留下继续联网的 mpv/FFmpeg。崩溃后旧 Socket 可能仍存在，其 UUID 文件名不会阻碍新会话；正常退出删除 Socket。

## 录音与失败处理

ffprobe 先检测实际音轨，连接关闭后启动 FFmpeg，以 `-map 0:a:0 -c:a copy` 保存原生编码。直接将独占创建文件的句柄交给 FFmpeg，不通过 shell 拼命令。输出名过滤路径字符并附加随机 ID；成功后用不覆盖目标的硬链接发布最终文件。

使用原生容器是兼容性选择：本机实验中 AAC 流拷贝到 Matroska 报采样率 / extradata 错误，而 ADTS 正常。HLS 的 AAC 音轨也输出 ADTS；不拼接不同电台或不同源的文件。

用户停止向 FFmpeg 发送 SIGINT 使其收尾，最多等待三秒后强杀；FFmpeg 因主动停止以 255 退出时不视为失败，仍以输出文件验证结果。录音开始与最终结果写 SQLite 和 JSON；文件使用绝对路径。FFmpeg 非零退出、无有效输出、直播提前 EOF、定时任务超时分别保存失败 / 中断状态。未正常收尾的记录在下次获得媒体锁后标记中断，保留原始文件。

录制过程中暂停播放仍然采集；切台先结束录音，新台不自动录制。当前电台录音复用实际起播地址，包含正在使用的备用线路。网络操作在 TUI 工作线程执行，界面不会等待网络；目录任务独立于媒体线程，播放起始、失败后的地址刷新和录音探测仍可能延迟后续媒体命令。退出时仍需等待正在执行的请求超时和录音收尾。ffprobe 与 FFmpeg 的流参数可能在断流、HLS discontinuity 或异常时间戳下失败，不会静默转码掩盖问题。

## 后续扩展

可在现有媒体核心外添加本地 IPC 服务以支持后台运行；单上游连接分发和环形缓存需另行设计背压、分段生命周期和跨线路边界。首版的 `Recorder` 与界面解耦，便于后续添加这些能力。
