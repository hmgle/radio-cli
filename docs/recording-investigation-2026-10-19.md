# AsiaFM 录音失败排查

排查日期：2026-10-19。环境：Linux，radio-cli 0.3.1 源码，FFmpeg 7.1.3。
只读检查本地数据库和原始录音；复现与测试使用独立临时目录。

## 本地证据

两条未完成记录均来自 AsiaFM高清音乐台，地址为
`http://asiafm.hk:8000/asiahd`。时间为北京时间：

| 记录 ID 前缀 | 开始时间 | 状态 | 文件大小 | 已保存音频 |
| --- | --- | --- | --- | --- |
| `a845d52f` | 10:34:40 | interrupted | 36,058 字节 | 数据库约 2.982 秒 |
| `4027cccd` | 10:36:12 | failed | 0 字节 | 无 |

第一条约 4.49 秒后收尾，错误仅为“直播源提前结束”。ffprobe 能识别为 AAC，
当前估算约 3.01 秒；解码检查还发现不完整的音频包。因此它包含部分可识别音频，
不能视为完整、无损坏的录音。原实现用摘要覆盖了底层日志，无法回溯具体断流细节。

第二条约 1.64 秒后收尾，日志包含：

- HTTP 提前结束，只收到 9,800 字节；
- AAC 解析错误，包括 `More than one AAC RDB per ADTS frame`；
- 无法确定音轨采样率，随后 `sample rate not set`，无法写入 ADTS 文件头。

同一地址在两次失败后分别录制成功。排查中的短时独立 HTTP 采样确认服务端为
Icecast 2.4.4，返回 `audio/aacp`，能取得 48 kHz、双声道 AAC。
直接运行与程序参数相同的 ffprobe，也观察到 AAC 解析警告后识别成功的情况。

以上支持“源连接间歇性提前结束，部分连接取得的起始音频不完整或异常”的判断。
无法仅凭这些记录区分服务器、网络链路或源端音频数据的具体责任；没有磁盘空间、
权限或本地发布失败的证据。FFmpeg 的通用升级提示本身不足以证明升级即可修复。
0 字节文件没有可恢复音频。

## 实现中的放大因素与修复

编码探测和实际录音使用不同连接。探测成功之后，录音连接仍可能立即被截断。
原录音命令没有启用 HTTP 重连，短暂故障会直接结束录音，或在取得采样率之前失败。

实际录音启用 `reconnect=1`、`reconnect_streamed=1`，并将
`reconnect_delay_max` 设为 2 秒。FFmpeg 在下一次指数退避超过该值时放弃该轮重试，
无需依赖较新版本的重试次数选项。保持原有读超时、定时录音截止和停止机制。
未启用 `reconnect_at_eof`，防止正常结束的有限音频被循环录制。
参数定义见 [FFmpeg HTTP 协议文档](https://ffmpeg.org/ffmpeg-protocols.html#http)。

诊断处理也做了修正：识别具体的 FFmpeg 进度键，保留包含 `=` 的错误信息；
保留最近 8 KiB 日志、换行和 UTF-8 字符边界；保留提前结束摘要背后的日志。
日志过滤终端控制字符，数据库和 JSON 元数据保存同样的诊断内容。

重连只提高连续录制的成功率，不能补回断线期间已经播出的直播音频，也不能修复
源端持续提供的损坏数据。重试耗尽后仍保留 `.part`，不会将未完成录音标为完整。

## 验证

修复前，本地模拟 Icecast 无长度响应在 AAC 前 32 字节处断开，复现了
“采样率未知、无法写入文件头、0 字节录音”；修复后同一测试重连成功并完成录音。
另一个场景在有效 AAC 录制开始后断流，修复后继续完成 6 秒定时录音。

新增回归覆盖启动截断、录制中截断、后续持续 503 时有界退出、保留错误日志尾部、
带等号的诊断、多字节 UTF-8、控制字符过滤以及数据库/元数据一致性。
既有测试继续检查有限源提前 EOF、原生四种编码、HLS AAC、停止和子进程回收。

最终检查：`cargo fmt --check`、全目标/全特性 Clippy（警告视为错误）、
`cargo test --all-targets --all-features --locked` 均通过：121 项通过，
1 项目录性能基准按默认设置跳过。`cargo build --release --locked` 成功。

在独立临时数据目录使用修复后的 CLI 对实际 AsiaFM 地址进行 5 秒定时录音，
生成 60,466 字节 AAC，状态 complete，媒体时长估算 5.059 秒。
这次短时成功不能证明源端长期稳定，也不能单凭它证明录制期间发生了重连；
自动重连的效果由上述可控断流回归测试验证。
